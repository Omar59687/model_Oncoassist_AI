# Research validation — Checkpoint 1

Status: provenance and evaluation-safety review, 2026-10-25. This document describes the **existing** saved results; it does not validate a clinical biomarker or change any model. Machine-readable status is in [research_validation.json](research_validation.json).

## Confirmed observations

- The three local CSVs match the three files in the [paper authors' dataset repository](https://github.com/Ibrahimalhurani/Dataset_and_Code/tree/0b55bfa24b608660562069802e12340370899b2b) after normalizing CRLF/LF line endings. Each has 404 unique SAMPLE_ID values with an identical ID/CLASS mapping across modalities: code 1 has 297 rows; code 2 has 107. Their intersection is 404, so omics alignment does **not** explain a reduction to 204. The existing script consumes all common samples ([loader](https://github.com/Omar59687/model_Oncoassist_AI/blob/10260e404a447e77f440288886101cf4db6fb6af/oncoassist_competition_ready.py#L68)).
- The [published paper, Table 2](https://doi.org/10.3390/a19020095) reports BLCA Low-TMB = 97 and High-TMB = 107 (204 total). Its Methods 3.2 describe a between-class t-test, fold-change filtering, and Benjamini–Hochberg FDR 0.01 for feature selection. The 200-row difference matches the difference in one count numerically, but **does not establish** which class code has which clinical meaning or why those records differ.
- The [authors' BLCA notebook](https://github.com/Ibrahimalhurani/Dataset_and_Code/blob/0b55bfa24b608660562069802e12340370899b2b/AE_CTGAN_BLCA.ipynb) (code cells 2, 3, 9) loads already selected feature tables; it does not show raw-feature selection, a sample exclusion rule, or a mapping from numeric CLASS to TMB. Its `iloc[:, 1:]` includes the final `CLASS` column in all three autoencoder inputs while also using `CLASS` as target. This is direct target leakage in that supplied notebook. It does not prove which exact notebook execution produced the paper's published numbers.
- Our [loader](https://github.com/Omar59687/model_Oncoassist_AI/blob/10260e404a447e77f440288886101cf4db6fb6af/oncoassist_competition_ready.py#L104) excludes `CLASS` from features, but maps the sorted codes to Low/High by assumption ([label mapping](https://github.com/Omar59687/model_Oncoassist_AI/blob/10260e404a447e77f440288886101cf4db6fb6af/oncoassist_competition_ready.py#L120)). The saved [research report](https://github.com/Omar59687/model_Oncoassist_AI/blob/10260e404a447e77f440288886101cf4db6fb6af/export_artifacts/research_outputs/research_report.json) records `label_semantics_verified=false`, `selected_augmentation.augmentation_source=bootstrap_fallback`, `ctgan_error=AssertionError`, and `external_validation.status=not_provided`. **These saved results are bootstrap-fallback results, not successful CTGAN results.**

## Unresolved; evidence required

1. **CLASS semantics:** obtain the source data dictionary or a per-SAMPLE_ID TMB table, cutoff, and code-to-category mapping from the data producer. Class frequencies, even the matching count of 107, are insufficient.
2. **204 versus 404:** obtain the paper's exact inclusion/exclusion list or sample manifest and preprocessing script, and reconcile 200 excluded IDs against the released CSVs. No such rule is visible in the published dataset/code.
3. **Feature-selection timing:** obtain the raw omics matrices, the t-test/fold-change/FDR selection code, and train/test or fold ID manifests. The paper describes supervised selection, but neither its placement relative to splitting nor the origin of the released 23 mGE, 42 mDM, and 14 mCNA features is reproducible from the supplied files. Selection on all labels before a split would leak test labels; this remains **unverified**, not a proven event.

## Interpretation limits for existing evaluation

The main script splits before fitting imputation, scaling, autoencoders, and augmentation ([training flow](https://github.com/Omar59687/model_Oncoassist_AI/blob/10260e404a447e77f440288886101cf4db6fb6af/oncoassist_competition_ready.py#L1654)). But its repeated/nested CV operates on matrices processed or encoded outside those folds ([CV call sites](https://github.com/Omar59687/model_Oncoassist_AI/blob/10260e404a447e77f440288886101cf4db6fb6af/oncoassist_competition_ready.py#L1814)). Three augmentation modes are compared using the same held-out test labels ([experiments](https://github.com/Omar59687/model_Oncoassist_AI/blob/10260e404a447e77f440288886101cf4db6fb6af/oncoassist_competition_ready.py#L1733)); those scores must not be used to select a model and then presented as untouched test performance. Calibration is fitted on augmented data with resampled near-duplicates ([calibration](https://github.com/Omar59687/model_Oncoassist_AI/blob/10260e404a447e77f440288886101cf4db6fb6af/oncoassist_competition_ready.py#L1766)). The saved report has no external validation. Treat all existing metrics as exploratory pending a fully isolated evaluation.

## Read-only verification

On 2026-10-25, compared all six CSV files from both repositories in memory: schema, unique IDs, equality after line-ending normalization, per-ID label consistency, intersection, and feature counts. All checks passed: 404 shared unique IDs; 297/107; 23/42/14 features. No training or artifact regeneration was performed.
